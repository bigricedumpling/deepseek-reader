# DeepSeek 面试准备 · 调研知识库

一个本地跑的阅读器兼编辑器。左边是分类与文档，中间读，右边是目录。正文可以直接改，所见即所得。

---

## 运行

```bash
npm install     # 首次运行
npm run dev     # → http://127.0.0.1:8090
```

**必须在 dev 模式下跑**。编辑、新建、删除都靠 Vite 的开发服务器中间件写磁盘，`npm run build` 出来的静态站是只读的。

改完代码可以跑这两个检查：

```bash
npm run check       # 导入自检：包导出名对不对、Vite 预构建有没有保留
npm run regression  # 真实浏览器回归：无头 Chrome 跑一遍编辑链路，验证不丢数据
```

`check` 防的是编译期发现不了的错——比如 `@phosphor-icons/vue` 导出的是 `PhSidebarSimple` 而代码里写了 `SidebarSimple`，编译和 HTTP 都是好的，浏览器一执行就白屏。

`regression` 会自建临时沙箱，只动沙箱里的文件，不碰真实内容。沙箱的 `node_modules` 用的是软链，所以它把自己的 Vite 缓存目录挪到了沙箱内部——否则跑一次回归就会覆盖主项目的 `node_modules/.vite`，把正在跑的 dev server 弄坏。

---

## 踩过的坑

这两个都不是编译期能发现的，记在这里免得再犯。

**依赖缓存过期会让整页白屏。** 反复装卸包时 Vite 会重新预构建，浏览器手里还是旧哈希的地址，请求全 504。表现为服务端 HTTP 全 200，页面一片空白。解法：删掉 `node_modules/.vite` 重启，再把动态引入的大包写进 `optimizeDeps.include`。

**所见即所得编辑器会把 markdown 重排，绝不能让它无声回写。** Crepe 解析再序列化之后，`---` 会变成 `***`，表格会被补齐空格对齐，裸链接会被包成 `<https://...>`，`@` 和 `_` 会被加反斜杠转义。内容不丢，但源码全变样，体积能翻倍。所以编辑器里有一道硬守卫：**没有真的敲过键盘、粘贴或拖放，一个字节都不许写回磁盘**。改这篇文档时要特别小心别把这道守卫去掉。

**同一份 Vue 被加载两次会报 `Cannot read properties of null (reading 'ce')`。** 这是上面那个问题的连带症状，`renderSlot` 拿不到 `currentRenderingInstance`。看起来像图标库坏了，实际是模块图混了新旧两份 runtime。同样靠清缓存解决。

## 它读写哪些文件

文档不在项目里，在上一级目录。`内容结构.json` 是文档树的清单：

```json
{
  "categories": [
    { "name": "调研", "docs": [
      { "title": "评测调研", "file": "评测调研.md" }
    ]}
  ]
}
```

`file` 是相对 `DeepSeek面试准备/` 的路径，可以指向已有的任意 md。新建的文档会落到 `内容/<分类>/<标题>.md`。

**改标题不动文件**：在正文里改一级标题，保存时只同步清单里的显示名，磁盘文件名保持不变。

想重新组织分类，直接改 `内容结构.json` 也行，界面上的操作只是它的一个编辑器。

## 编辑

**没有编辑模式。** 正文打开就是可编辑的，跟 Notion 一样——点进去直接写，停手自动保存。

| 操作 | 效果 |
|---|---|
| 直接点正文 | 落光标开始写 |
| 打斜杠 `/` | 唤出插入菜单：标题、列表、引用、代码块、表格、图片、数学公式 |
| 停手约 0.8 秒 | 自动保存，底栏显示「已保存 14:32」 |
| `⌘S` | 立刻保存 |
| 拖块左侧手柄 | 移动或删除整块 |

工具栏上没有编辑和保存按钮，因为不需要。

**排版就是阅读排版。** 编辑器用的字体、字号、行距、阅读宽度跟你设置的一模一样，所以不存在切进切出时跳一下的问题。

**格式安全，三层保护**：

1. **没敲过键盘就不写盘。** 编辑器创建时会解析再序列化一遍 markdown，这个过程会改动一些写法。但只要用户没真的输入过，一个字节都不会回写。
2. **存盘前还原编辑器的外观改动。** `***` 还原成 `---`，表格去掉对齐空格，拆掉自动链接的尖括号和多余转义；表格单元格逐个跟原文比对，没改过的整格沿用原文。
3. **还原不回来的，自动切源码编辑。** 有些结构编辑器根本表达不了，最典型的是**表格单元格里的 `<br>`**，会被直接丢掉。打开时会检测一次，发现这种情况就自动换成源码编辑并给出说明，绝不静默损坏原文。

所以：格式简单的文档用所见即所得，带 `<br>` 断行表格的文档自动走源码。

## 管理文档树

左侧分类和文档都支持增删改：

| 操作 | 位置 |
|---|---|
| 新建文档 | 顶部「新建文档」，或悬停分类名点 `+` |
| 重命名文档 | 悬停文档，点铅笔 |
| 删除文档 | 悬停文档，点垃圾桶 |
| 重命名分类 | 悬停分类名，点铅笔 |
| 删除分类 | 悬停分类名，点垃圾桶 |
| 新建分类 | 工具条最右的文件夹加号 |

工具条的滑杆按钮管分组与排序：

- 分组方式：按分类 / 单列表
- 排序方式：手动 / 最近更新 / 按名称

每篇文档右侧显示最近修改时间。分类可以展开收起，收起状态记在本地。

**删除走回收站**：文件不会真被删掉，会挪到 `DeepSeek面试准备/.回收站/`，文件名前面加时间戳。

## 不会丢东西的几个地方

- 正文改过没保存时，切文档、点搜索结果跳转、关标签页，都会先拦一下
- 拦截弹窗给三个选择：保存并切走、丢弃改动、取消
- 删除是挪进回收站，不是直接删
- 保存时检查正文一级标题，改了只同步左侧显示名，不动文件名

工具栏里跟排版有关的：

| 按钮 | 作用 |
|---|---|
工具条只有四组，其余按类别收进菜单：

| 组 | 里面有什么 |

| 外观 | 主题（跟随系统 / 浅色 / 深色）、缩放（80% 到 150%） |
| 导出 | 导出 markdown、打印 / 导出 PDF |
| 目录 | 右侧目录开关 |

缩放同时作用于字号与阅读宽度，每行字数基本不变，只是整体变大变小。

「排版」面板里可以调：

| 项 | 选项 |
|---|---|
| 正文字体 | 衬线 / 无衬线 / 楷体 / 苹方 |
| 中文加粗 | 特黑 900 / 加粗 600 |
| 中文斜体 | 楷体 / 不替换 |
| 段落 | 段距式 / 缩进式 |
| 字间距 | −0.02 到 0.12 em 滑条 |

**中西文分开选。** 字体栈里西文在前、中文在后，浏览器按字符回退天然分流，所以「衬线」是 TeX Gyre Pagella 配思源宋体，不是二选一。

**中文斜体不做倾斜变形**，按中文排版传统换楷体。**中文加粗走宋体 Black 面**，不是把常规面加粗一档——那样在 16pt 下几乎看不出来。

**中西文之间自动留缝。** 汉字与西文交界处插一个 thin space，代码块和行内代码里的汉字不参与。

## 排版约定

内容按这些规矩写，改的时候也照着来：

- 不用间隔号，正文元素之间用顿号、逗号或换行
- 尽量不用括号，装饰性的括注一律并进句子。公式和代码除外
- 不写观点、不写总结段、不写「这意味着什么」
- 数字多、又是几套口径对照的时候用表格，不要堆成一句话
- 表格单元格里项目多就用 `<br>` 断行，不要写成一大串
- 标题只到三级

## 表格

**列宽按内容自适应，不搞等宽。** prosemirror-tables 的默认样式是 `table-layout: fixed` 加 `width: 100%`，那会让所有列强制等宽——文字多的列被挤到每行只剩几个字，行高拉得老长。这里改成了 `table-layout: auto`。

**表格默认与正文等宽**，看起来和上面的段落对齐。要更宽可以在「排版」面板里切成「铺满」，用满可用宽度。

**长 URL 允许在任意位置断行。** 这条是关键：链接不可断的时候，自动布局会把整列宽度让给它，真正文字多的列反而被挤扁。修之前「判分方式」列只有 150px、「链接」列独占 376px；修完是 212px 对 248px。

工具栏「排版」面板里可以切表格宽度（铺满 / 同正文）和对齐（左 / 中 / 右）。

## 打印与导出 PDF

按「打印 / 导出 PDF」走浏览器原生分页，分页规则写在 `style.css` 的 `@media print` 里：

- 侧栏、目录、工具条、底栏都不进纸
- 段落留孤行寡行各两行，不把一行单独甩到另一页
- 标题不单独留在页尾，标题后紧跟的段落不另起一页
- 表格、代码块、图、公式尽量不跨页；表格跨页时表头自动重复
- 链接会把完整地址印在括号里，纸上点不了也能查

## 已知限制

- 所见即所得模式的 markdown 往返可能有细微重排，格式复杂的文档建议用源码模式
- 接口没有鉴权，只监听 `127.0.0.1`，不要暴露到公网
- 静态构建产物没有编辑能力
- 回收站不会自动清理，攒多了自己去 `.回收站/` 里删
