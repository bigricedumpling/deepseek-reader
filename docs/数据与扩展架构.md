# 数据与扩展架构

更新日期：2026-09-29。本轮仅修改本地，未发布。

## 内容如何保存

正文继续是普通 Markdown 文件。PDF、HTML 和原有附件保持文件形式。页面图标、封面、目录顺序、公开与锁定规则改由 `知识库/.reader/state.sqlite` 管理；文档有稳定 UUID，改名和移动不再改变身份。

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 界面 | `src/components`、`src/stores` | 编辑、导航、冲突提示、图标与封面 |
| HTTP 入口 | `server/content-api.js` | 身份、作用域、路径和权限检查，调用服务 |
| 文档服务 | `server/services/documents.js` | 元数据、历史、搜索、Agent 凭据 |
| 资源服务 | `server/services/resources.js` | 持久图片、资源归属、旧地址兼容 |
| 存储 | `server/storage/workspace.js` | SQLite、稳定 ID、原子写入、操作日志和恢复 |
| Agent 适配 | `plugins/reader-workspace` | MCP 与命令行，共用 HTTP 权限检查 |

旧的 `.知识库.json`、`.顺序.json`、`.分享.json` 等只作为首次迁移来源。迁移后不要继续编辑旧 JSON 来修改配置。会话单独保存于 `reader/.runtime/`，Agent 令牌仅保存哈希；它们不进入可移植内容备份。

## 保存、改名与图片

读取正文返回 `id`、`revision`。保存必须带上读到的版本：缺失返回 428，旧版本返回 409。界面保留本地修改并展示冲突，可另存副本或合并，避免外部 Agent 和编辑器互相覆盖。

写入采用临时文件替换；涉及文件和元数据的修改使用 SQLite 事务与文件恢复日志。进程中断后，启动时按提交记录恢复。历史正文以 UUID 命名，保留最近 100 份，避免中文长路径超出文件名限制。

图片先上传为持久资源再写入正文。资源归属于文档 UUID，公开访问按文档当前权限判断。改名、移动后旧图片地址继续解析，隐藏文档后旧地址也不会绕过权限。

在阅读器外修改正文可以继续使用；再次保存时会检查冲突。在外部改名或移动，点击侧栏重新扫描并确认迁移。当前通过文件系统标识检测移动；跨磁盘复制后删除原文件无法可靠自动认定，应通过阅读器执行移动。

## 迁移、备份与恢复

运行环境要求 **Node.js 24 或更新版本**，使用内置 SQLite。

```bash
# 在 reader 目录执行，DOCS_ROOT 必须指向真实内容根目录
DOCS_ROOT=/path/to/知识库 node scripts/migrate-workspace.mjs
DOCS_ROOT=/path/to/知识库 node scripts/backup-workspace.mjs /path/to/新备份目录
node scripts/restore-workspace.mjs /path/to/新备份目录 /path/to/全新恢复目录
```

迁移可重复运行。备份包含正文、附件、页面设置、权限及历史索引；恢复只允许写到不存在的新目录。运行中不要单独复制 SQLite 主文件，应使用备份脚本。外部编辑器不参与数据库锁，备份时请暂停外部文件写入。

备份包含私有内容，不能直接作为公网发布包。公开发布仍只挑选公开库，不自动同步本地面试资料。

## Agent 接入

左下角管理工作区菜单中打开 Agent 连接，选择一个知识库、只读或可写和有效期。令牌只显示一次，可以随时撤销。插件通过环境变量读取令牌，避免写入仓库。

插件包：`plugins/reader-workspace`。既提供 MCP stdio，也能作为命令行工具。凭据按知识库稳定 ID 限定范围，库改名不会扩大范围。文档写入要求版本；创建等操作可带 requestId，重试不会重复新建。插件目前已完成协议与服务测试，**未安装到用户的 Agent 环境**。

## Markdown 兼容问题

目前富文本编辑依赖 Markdown 解析和重新序列化。保护检查发现内容不能可靠往返时，会让整篇退回源码；它不是文件识别失败，也不代表 Markdown 损坏。AI 输出的 HTML、非标准表格、脚注或特殊扩展可能触发这一情况。

不建议直接取消保护，也不应要求每次都把全文重排。下一阶段建议：

1. 以 CommonMark / GFM 为基本格式，明确支持的数学、颜色和折叠扩展。
2. 解析时保存每块的原文和位置；未改动块直接写回原文。
3. 不支持的结构显示为可预览的原文块，只对该块保留源码编辑，其余内容正常富文本编辑。
4. 引用链接、脚注、嵌套列表等有跨块依赖，必须作为整体保留和校验，不能简单按空行切割。
5. 用现有真实文档做往返夹具，要求图片地址、表格单元格、脚注和代码不丢失。

本轮保留现有安全检查，尚未替换整套 Markdown 解析器。新增封面和图标独立于正文，不会增加 Markdown 语法要求。

## 并排排版与图片粘贴

并排内容保存在版本化的 `reader-columns` Markdown 扩展块中，每列仍是独立 Markdown。支持二列与三列、列内直接编辑和手机单列显示；HTML 导出带有对应布局。普通 Markdown 工具会看到扩展块源码。当前不支持多层嵌套分栏和自由调整列宽。

拖拽块到目标左右边缘时只显示竖线；也可在段落中使用 Alt + Shift + 右方向键，与上一个块并排。文本/图片组合、三列上限、直接编辑和重新加载已经验证；自动化环境尚未可靠完成原生鼠标拖放，因此不把该项记录为浏览器实测通过。

图片粘贴先保存附件，再按映射后的光标位置插入。已验证段落开头、中间和空段落不会丢失原文，浏览器验证了持久资源上传及段首插入。弹层使用统一的进入/退出时长，并尊重系统减少动态效果设置；标签保留同一容器完成数量变化的过渡。
