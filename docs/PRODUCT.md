# 产品定位

## 为什么需要 Typocket

人与 Agent 一起工作的过程，会产生研究笔记、草稿、参考资料、网页和附件。文件方便 Agent 直接读写，却缺少适合人持续阅读、整理和再次进入工作的界面。传统在线文档适合团队协作，但账号、导入导出、API 接入和线上组织结构，对以个人文件为中心的工作增加了负担。

Typocket 为这类工作补上阅读与整理的一环：让工作区成果可以被舒服地阅读、适度编辑、主动收录、长期找回。它首先是个人文档工具，DSH 是目前主要入口。

## 面向谁

已有 Agent 工作流，需要反复调研、写作、整理或交付资料的个人。用户关心内容能留在本机、能追溯、能继续交给 Agent 使用，也希望需要时给他人查看。

它不是只能看 Markdown 的格式预览器。Markdown 是主要写作载体；PDF、H5 是工作资料的一部分，目前定位为预览，不能据此宣称支持 PDF 编辑或任意格式转换。

## 三个清楚的对象

- **工作区**：任务现场，原文件归项目管理。
- **抽屉**：主动维护的长期资料，收录产生独立副本。
- **分享快照**：主动选择对外提供的内容，手动更新。

工作区浏览记录属于工作区入口，不是一个特殊抽屉，也不是所有抽屉的阅读历史。界面应保留完整名称，不能只让用户猜图标。收录不删除浏览记录，不意味着原文件自动同步。

## 设计原则

- 常用操作直接可见；补充解释放 tooltip 或帮助文档，避免每个弹窗写一段说明。
- 状态使用图标与短文本，关键含义不能只依赖颜色或悬停。
- 图标、间距、弹层宽度和返回路径形成统一规则；窄视口不能靠裁切隐藏操作。
- 发生冲突时先保留两份内容；不能用“最后一次保存”静默覆盖另一方。
- 用户打开的是自己的资料，安装、升级、构建、卸载都不应悄悄换库或搬动文件。

## 本阶段不扩展

不建设多人实时协作、组织账号系统、自动全盘收集、双向同步。保留有限分享和 Agent 授权，不把这些高级功能变成首次阅读的必经流程。

## 如何判断做对了

新用户能从安装进入空抽屉；能读一份工作区文档并清楚知道收录后在哪里；重启还能找回资料和阅读状态；面对冲突或误修改知道如何找回；升级不要求重新部署服务。这些流程比支持更多格式或更换语言优先。
